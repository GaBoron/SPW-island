# 故障排查

[← 文档首页](README.md)

## 先试这几步

很多问题不用重装，先按下面的顺序排一下：

1. 确认下载的是 `spw-island-<版本>.spmod`，并且插件已经在 SPW 中启用；
2. 切换一次歌曲，必要时重启 SPW；
3. 歌词问题先确认 SPW 自己已经能显示歌词；
4. 找不到词岛时先点一次“找回词岛”；
5. 时序或实验功能异常时，先恢复到 1× 播放并暂时关闭实验性多行歌词。

拿一首本地歌曲、默认设置、1× 播放做对照，通常很快就能看出问题是在歌曲数据、歌词源、平台环境还是词岛本身。

## 安装与显示

### 插件没有出现在 SPW 插件列表

先确认：

- 下载的是 `.spmod` 插件包，不是 `-source`；
- `.spmod` 没有被解压后又把里面的文件夹当插件装进去；
- SPW 支持 Workshop API dev23，宿主使用 Java 25 或更高版本。

请通过 SPW 的创意工坊 / 插件管理导入 `.spmod`。详细步骤见 [安装与更新](installation.md)。

### 插件启用了，但词岛完全不显示

检查“显示词岛”“暂停时隐藏”，Windows 再检查“全屏时隐藏”。如果用过多显示器，也可能只是词岛还停在另一块屏幕的位置。

最直接的处理办法是：

**SPW 插件设置 → 找回词岛**

它会重新显示词岛并移回主屏幕顶部；同时解除鼠标穿透。

`Ctrl+Shift+D` 默认在 SPW 内显示 / 隐藏词岛。若无反应，检查插件的快捷键权限和 SPW 快捷键管理中的绑定与冲突。

### 词岛突然消失

常见原因有：

- 开了“暂停时隐藏”；
- Windows 开了“全屏时隐藏”；
- 开了悬停自动隐藏；
- 显示器连接状态变化后位置跑掉。

动态壁纸、桌面增强软件或某些铺满屏幕的窗口也可能被 Windows 判断成全屏。关掉“全屏时隐藏”后立刻恢复，通常就是这一类情况。

### 被最大化窗口遮挡，或显示桌面后无法恢复

Windows 下会校验词岛的原生置顶、可见和最小化状态，并在显示设置允许时恢复。先确认“显示词岛”已开启，以及暂停、全屏或悬停隐藏条件没有触发。

若仍然出现，在问题发生后导出诊断包，并说明是否涉及 SPW 启动时被遮挡、窗口最大化或 `Win+D`。诊断记录包含置顶请求的错误码、请求前后状态和重叠的上方窗口，不记录窗口标题；这些记录仍不能代替实际画面的截图或录屏。

### 开启鼠标穿透后无法操作词岛

这是正常行为。鼠标事件已经交给词岛下面的窗口了。

可以从系统托盘关闭穿透，或者直接用“找回词岛”恢复。

## 歌词与时序

### 只有歌名，没有歌词

先确认 SPW 自己能显示当前歌曲歌词。词岛能拿到歌名，不代表 SPW 已经把歌词行传过来。

可以依次试：

1. 切到另一首歌再切回来；
2. 如果用了其他歌词插件，确认它已经完成歌词加载；
3. 重新播放或重新加载当前歌曲。

本插件不会主动联网搜歌词。需要自动获取逐字歌词时，可以搭配 [SPW-Lyrics](https://github.com/GaBoron/SPW-Lyrics)。

如果只在多个歌词插件同时启用时出问题，反馈时把插件组合一起写上。

### 歌名也不对，或者切歌后还停在上一首

先再切一次歌曲。如果仍然能复现，最好记录：

- 本地歌曲还是网络歌曲；
- SPW 自己显示的曲目信息是否正确；
- 是否只发生在插件刚启用后的第一首歌；
- 再切一次歌曲后会不会恢复。

这些信息比单独一张截图更有用。

### 逐字高亮整体偏早或偏晚

在 SPW 插件设置里调整“逐字高亮偏移 ms”：

- 正值：高亮提前；
- 负值：高亮延后。

这个设置只能修正整体偏差。不同歌曲需要完全不同的 offset，通常是歌词源自己的时间轴差异。

### 调整播放倍速后明显不同步

词岛会根据 SPW 的位置回调估计倍速。刚切换后等两次位置回调再观察；如果仍明显不同步，请记录播放倍速、歌词来源、歌曲时间点以及 SPW 版本。不要靠不断改 offset 去补倍速问题。

### 实验性多行歌词异常

如果出现不该重叠的歌词、间奏保留错行，或者只有部分歌曲表现异常，先关闭“实验性多行歌词”看默认单行模式是否正常。

只有实验模式出问题时，反馈最好附上具体歌曲、歌词来源和能稳定复现的大致时间点。

## 封面、进度与频谱

### 看不到专辑封面

插件先查询 SPW 公开 API 返回的内嵌封面，再读取本地能访问到的封面：

1. 音频内嵌封面；
2. 同目录 `cover.jpg` / `cover.png`；
3. 同目录 `folder.jpg` / `folder.png`。

网络歌曲、不可访问文件或本来就没封面的歌曲会显示占位图。

如果本地歌曲明明有封面，可以换另一首本地歌对比，并确认 SPW 当前播放路径确实指向那个文件。

### 开启封面取色后没变化

先看封面本身有没有成功读到。显示占位图时，歌词、背景和频谱都会继续用默认颜色。

另外，取色会避开近黑和近白区域，不是直接读封面中心像素，所以结果和肉眼认定的“主色”可能不完全一样。

### 进度条不能拖，或者总时长是 `--:--`

拖动进度需要可靠的歌曲总时长。网络歌曲、本地文件暂时不可读，或者某些格式无法可靠解析时长时，进度控制会受限。

这不会影响歌词、上一首、播放 / 暂停和下一首。

如果只有某一种本地音频格式一直读不到时长，提 Issue 时把格式写上。

### Windows 实时频谱不动

先确认当前两侧信息设置里确实有频谱、歌曲正在播放，而且没有开启低性能模式。

实时频谱还需要：

- Windows build 20348 或更高；
- 可用的 .NET Framework 4.x；
- 共享模式音频输出。

独占模式、ASIO 或其他绕过共享音频链路的输出方式可能捕获不到。先切到共享模式测试最省事。

捕获启动失败时，插件会退回模拟频谱，并在当前插件生命周期里提示一次原因。歌词不会因此停掉。

### 低性能模式下频谱不像真实音乐

正常。低性能模式会主动关掉实时音频捕获，改用轻量模拟频谱。

### Linux 实时频谱显示模拟或不动

先检查“两侧信息”包含频谱、正在播放且未启用低性能模式，然后查看托盘“关于与状态”里的频谱来源。需要 PipeWire 服务和 PATH 中的 `pw-record` / `pw-dump`。找不到 SPW 播放流时会等待并使用模拟频谱；切歌或切换设备后应自动重连。ALSA 直出、独占输出或无法匹配进程身份时不会改采其他应用。

### Linux 穿透时没有悬停隐藏

X11 和 KDE Wayland 可直接使用。GNOME Wayland 45–50 需先在插件配置点击“安装 GNOME 悬停隐藏支持”，首次安装或更新后保存工作并重新登录。查看托盘“关于与状态”里的指针连接状态；连接失效会恢复显示并重试。需要重新操作词岛时，在托盘选择“找回词岛”，或从 SPW 插件设置点“找回词岛”。

### Wayland 上移开鼠标后控件仍然展开

移开鼠标后，词岛应收起控件；移入播放按钮或进度条时保持展开，拖动期间则等待松开。如果控件持续展开，请记录桌面版本、是否启用穿透、词岛与目标窗口的缩放比例，并附上进入词岛后移到原生 Wayland 窗口的步骤。

## 菜单、设置与字体

### Windows 托盘图标启动后短暂出现

如果已在 Windows 中将词岛图标收进隐藏区域，但启动 SPW 后图标短暂出现、随后自行收起，这可能是系统的托盘预览；仅凭短暂出现不能判断隐藏设置丢失。Windows 允许系统临时展示图标，最终位置由系统与用户设置决定，参见 [微软通知区域说明](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area)。

如果图标持续不收起、每次启动都新增设置项，或托盘程序报错，请复现后导出诊断包，并注明 Windows 版本、SPW 来源（Steam / Microsoft Store）及图标出现了多久。

### 快捷菜单里找不到某个设置

托盘 / 右键菜单只保留显示、穿透、悬停隐藏、低性能模式和恢复操作。翻译、逐字高亮、外观、多行歌词、暂停 / 全屏隐藏，以及字体、取色等完整设置均在 SPW 原生插件配置页里。频谱来源和指针连接详情见“关于与状态”。

菜单里没有，不代表功能被删了。

### 字体异常、缺字或自定义字体效果不对

默认歌词在 Windows 和 Linux 均使用内置 MiSans，不需要额外安装字体。

Windows 通过“歌词字体”窗口设置；Linux 仍填写已安装字体名称。自定义字体后：

- 只影响歌词；
- 找不到该字体时会退回内置字体；
- 某个字符缺失时先用内置字体补字，韩文等仍缺失的字符继续使用系统字体；
- 选择器只列出所选字体实际包含的字型，并直接使用对应的真实字面；字型无法解析时按最接近的已有字重回退。

极少数字符连系统字体也没有时，仍可能出现缺字框。

## 性能

### 液态玻璃未生效或背景更新慢

先确认当前系统支持液态玻璃、已在插件设置中选中该背景样式，且未启用低性能模式。Windows 11 需要 SDR 显示环境；GNOME 50 首次使用需安装配套扩展并重新登录。

仍无法显示时，打开“关于与状态”查看背景状态和失败原因，再从插件设置导出诊断包。支持范围见 [液态玻璃](compatibility.md#液态玻璃)。

### 词岛卡顿或动画不流畅

先开“低性能模式”试一下。它会降低常规刷新率，简化逐字高亮和部分动效，并停止实时音频捕获。

如果低性能模式下仍然明显卡顿，反馈时最好说明：

- Windows 还是 Linux；
- 系统、SPW 和插件版本；
- 是否开启实验性多行歌词；
- 是一直卡，还是只在展开、拖动、切歌或逐字歌词时卡。

“整个 SPW 都卡”和“只有词岛动画掉帧”不是同一类问题，尽量分清楚。

## Linux

Linux 目前仍是实验性支持，完整差异见 [兼容性与限制](compatibility.md#linux-实验性支持)。

### 词岛上右键没有菜单

当前 Linux 快捷设置入口在系统托盘，词岛区域右键暂不提供菜单。也可以直接用 SPW 原生插件设置页。

### 看不到托盘图标

部分 Linux 桌面需要启用系统托盘支持，GNOME 通常需要启用 AppIndicator 扩展。

如果仍看不到图标，可从 SPW 插件设置管理词岛。问题持续时，请导出诊断包并提交 Issue。

### 窗口空白、透明或内容不刷新

先用“找回词岛”排除隐藏设置和位置问题，再分别对比默认绘制与软件绘制。完全退出 SPW，在 Steam 启动选项中填写：

```sh
SPW_ISLAND_RENDERER=software %command%
```

重新启动并复现后导出诊断包。这个变量只让 Linux 词岛的独立 JVM 使用 Java2D 兼容绘制；低性能模式仍按原有预算限制刷新率。删除该启动选项，或改为 `SPW_ISLAND_RENDERER=auto %command%`，即可恢复默认绘制。

如果软件绘制正常而默认绘制空白，可将问题缩小到 Skiko / OpenGL 显示路径，但还不能直接认定是显卡驱动。请提供两种模式的诊断包，以及桌面、X11 / Wayland、显卡和驱动版本。

诊断中的 `awtGraphics` 与 `awtCanvasGraphics` 分别记录窗口和 Skiko Canvas 的 AWT 配置、颜色位深、各通道位数及 alpha 掩码。`defaultColorModel` 对应当前配置；`translucentColorModel` 是请求透明颜色模型的返回值，不能单独证明原生窗口或 OpenGL 缓冲区正在使用该格式。若绘制停滞，日志中的相关线程栈也有助于区分绘制异常与缓冲区交换阻塞。

### 拖动松手后短暂闪回原位置

先检查是否安装了最新版本，再连续拖动词岛到不同位置，观察松手后是否保持在目标位置。若位置仍会跳回，请在 Issue 中附上录屏、桌面版本、缩放比例和是否启用鼠标穿透。

### 平台专属设置没有效果

请先在 [兼容性与限制](compatibility.md) 中确认该功能支持当前系统。Linux 暂不支持词岛区域右键菜单和前台全屏自动隐藏。

## 提交 Issue

上面的办法都没解决，可以到 [Issues](https://github.com/GaBoron/Dynamic-Lyrics-Island-for-SPW/issues) 反馈。

在 **SPW 插件设置 → 工具与关于** 中点击“导出诊断包”，复现问题后将生成的 ZIP 附到反馈中。“打开日志目录”可直接查看日志；这两个入口不依赖词岛窗口或托盘正常显示。

诊断包的 `latest-state.json` 列出导出进程最近记录的状态和采样时间，可判断记录是否已过期。Linux 独立界面的窗口状态见对应运行编号的 UI 日志。

日志默认记录异常、关键状态变化及设置修改，保留 10 天，目录中的日志总量受容量限制。Windows 使用 `%LOCALAPPDATA%\spw-island\logs`；Linux 使用 `$XDG_STATE_HOME/spw-island/logs`，未设置时使用 `~/.local/state/spw-island/logs`。导出的 ZIP 位于日志目录的上一级，不会自动上传。

过期日志移入系统回收站。回收站不可用时保留文件，并在达到容量限制后暂停文件记录；Linux 自动清理需要 `gio` 工具。

日志不主动记录歌词正文或歌曲路径，并对常见路径、凭据格式作脱敏。异常堆栈仍可能包含个人信息，分享前请检查。窗口状态和绘制进展只能说明插件及系统报告的状态，不能证明系统最终合成的画面实际可见。

至少写清楚平台、系统版本、SPW 版本、插件版本、复现步骤，以及问题是每次都出现还是偶发。截图或录屏尽量同时带上 SPW 和词岛状态。

不同问题再补这些信息会更好：

- 歌词：歌曲、歌词来源、出问题的大致时间点；
- 频谱：音频输出方式，是否使用 ASIO / 独占模式；
- 封面：本地还是网络歌曲，封面是内嵌还是同目录文件；
- 多显示器：显示器数量、缩放比例、主屏；
- Linux：桌面环境，以及 X11 / Wayland / XWayland。

尽量把“期望发生什么”和“实际发生什么”都写出来，比只说“不能用”更容易定位。
