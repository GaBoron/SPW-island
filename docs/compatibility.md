| 平台 | 状态 | 说明 |

| Windows 10 / 11 x64 | 主要支持平台 | 功能最完整，也是主要验证环境 |

## 歌词和 SPW

Windows 托盘图标和实时频谱需要本机的 .NET Framework 4.x，频谱的其他运行条件见下文。字体选择器使用插件内置的 Compose 界面。

词岛只显示 SPW 已经加载的歌词，不会自己联网搜索、上传歌词，也不会修改歌曲或歌词文件。需要自动获取逐字歌词时，可以搭配 [SPW-Lyrics](https://github.com/GaBoron/SPW-Lyrics)。

默认单行模式主要依赖公开的歌词回调。实验性多行歌词会尝试拿到更完整的歌词时间轴，所以对宿主版本和内部行为更敏感；出问题时关掉即可回到普通模式。

同时启用多个会参与歌词加载的插件时，SPW 的回调顺序也可能影响最终结果。如果问题只出现在某个插件组合下，反馈时最好把组合一起写上。

### 非 1× 播放速度

词岛根据 SPW 回传的播放位置估计倍速，用于两次位置回调之间的逐字高亮和进度显示。刚切换倍速时需要收到后续位置回调才能更新估计；如果宿主停止回传位置，时间轴会在短时间后冻结。

## 本地歌曲、封面和总时长

封面和总时长主要从当前本地音频文件读取，不依赖 SPW 私有曲库数据库。

封面按下面的顺序尝试：

1. 音频文件内嵌封面；
2. 同目录 `cover.jpg`；
3. 同目录 `cover.png`；
4. 同目录 `folder.jpg`；
5. 同目录 `folder.png`。

网络歌曲、不可访问文件或没有封面的歌曲会使用占位图。

展开后的进度条需要可靠的歌曲总时长。本地音频通常没问题；网络歌曲、无法访问的文件或不能可靠解析时长的格式，可能只能显示当前播放时间，不能提供完整 seek 进度条。歌词和上一首 / 播放暂停 / 下一首仍可正常用。

## 实时频谱与音频输出

Windows 的实时频谱只捕获 SPW 进程及其子进程的音频，不会读取麦克风、其他应用或完整系统混音，也不会保存录音。

运行条件：

- Windows build 20348 或更高；
- 可用的 .NET Framework 4.x；
- 共享模式音频输出。

独占模式、ASIO 或其他绕过共享音频链路的输出方式可能无法捕获。实时捕获失败时，词岛会退回轻量模拟频谱，不影响歌词显示。

Linux 实时频谱需要 PipeWire，以及 PATH 中可用的 `pw-record` 和 `pw-dump`（发行版通常放在 `pipewire-bin` 或 `pipewire` 包中）。只选择由 SPW 或子进程拥有的播放流，不采集默认音源或系统混音。找不到目标流时暂用模拟频谱；音频流重建后自动重新连接。绕过 PipeWire 的 ALSA 直出或独占输出无法捕获。

当前 Linux 同时有多个 SPW 播放流时，选择最新的活动流，不叠加多个流。托盘菜单会标明实时、等待连接或模拟频谱状态。频谱封面取色与音频后端无关。

低性能模式会主动停用实时音频捕获，所以这时看到模拟频谱是正常的。

## 快捷键和窗口行为

`Ctrl+Shift+D` 目前只在 SPW 内生效，不是系统级全局快捷键。

Windows 的“全屏时隐藏”依赖前台窗口判断。动态壁纸、桌面增强软件或其他铺满屏幕的窗口偶尔也会被识别为全屏。

Windows 和 Linux 均内置 MiSans。歌词缺字时先尝试 MiSans，再回退到系统字体；系统仍无对应字形时才会显示缺字框。

## Linux 实验性支持

Linux 版本复用大部分歌词和 Swing UI，但词岛窗口运行在独立界面进程里。

需要：

- Linux x64；
- 支持 Java / Swing 插件的 SPW Linux 宿主；
- `/usr/bin/python3`；
- GTK 3；
- X11 或 XWayland。

界面直接使用 SPW 自带 JVM，不需要另外装 Java；Python helper 只用标准库。

快捷设置通过 GTK 托盘提供，优先使用 AppIndicator / Ayatana AppIndicator，不可用时尝试 GTK StatusIcon。不同桌面环境的托盘支持差异很大；如果看不到托盘，仍然可以从 SPW 原生插件设置页管理词岛。

Linux 窗口仍使用 X11 / XWayland。普通悬停展开通过窗口进入/离开事件判断，不依赖跨原生 Wayland 窗口可能失效的全局坐标。鼠标穿透通过空输入区域实现，托盘和插件设置中的“找回词岛”可解除。

穿透时的悬停隐藏需要可靠的全局指针：X11 直接支持；KDE Wayland 会在启用时临时加载 KWin 脚本，关闭功能或退出时卸载，不修改永久桌面设置。指针过期或桥接断开时自动恢复显示并尝试重连。GNOME Wayland 45–50 通过只读配套扩展提供指针，需从插件设置安装，首次安装或更新后重新登录。其他 Wayland 桌面目前保持显示，鼠标穿透仍可使用。KDE 真机、多显示器及混合缩放仍需按桌面环境验证。

Linux 目前没有前台全屏检测、Windows 式额外置顶强化和词岛区域右键菜单；这些设置不会出现在 Linux 配置页里。

窗口位置与播放进度在松手后保留提交值，宿主确认后再切换状态，避免旧状态造成回弹。X11、GNOME / KDE Wayland 与 wlroots 等环境仍需要分别验证，所以 Linux 目前仍标记为实验性支持。

如果上表中标记为支持的功能实际没有正常工作，请看 [故障排查](troubleshooting.md)。更底层的实现和平台架构放在 [开发指南](development.md)。
